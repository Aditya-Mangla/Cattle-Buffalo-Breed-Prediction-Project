# Breed Reader — Cattle & Buffalo Breed Recognition

**Convolutional Neural Network -based breed identification for Indian cattle and buffaloes**

Upload a photo, get the breed back in seconds — with confidence scores and top-3 alternatives, not just a single forced guess.


##  About

Breed Reader identifies indigenous cattle and buffalo breeds (Gir, Sahiwal, Murrah, and others) from a single photograph using a fine-tuned computer vision model. It's built around the SIH 2025 problem statement **"Image-based Breed Recognition for Cattle and Buffaloes of India"**, aligned with the **Bharat Pashudhan App** and **Rashtriya Gokul Mission** — helping field workers and farmers get fast, consistent breed identification without needing expert manual verification.

##  Features

- **Instant breed prediction** from a single uploaded photo
- **Top-3 alternatives with confidence scores** — surfaces uncertainty instead of hiding it, so low-confidence predictions can be flagged for manual review
- **Explainable predictions** via Grad-CAM visualizations, showing which part of the image (horns, hump, coat pattern) the model actually used
- **Reliable, reproducible training pipeline** — stratified train/val/test splits, class-imbalance handling, automated checkpointing, and dataset validation before training even starts
- **Drag-and-drop web tester** for quickly trying the model without a full frontend

##  Tech Stack

| Layer | Technology |
|---|---|
| Model | PyTorch + `torchvision` (EfficientNetV2-S, transfer learning) |
| Training | Jupyter Notebook, scikit-learn, Grad-CAM (custom hook-based implementation) |

##  Getting Started

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Prepare your dataset
Arrange breed images as one folder per breed:
```
dataset/
├── Gir/
├── Sahiwal/
├── Murrah/
└── ...
```

### 3. Train the model
Run `project.ipynb` top to bottom. It validates the dataset, creates a stratified split, trains EfficientNetV2-S via transfer learning, evaluates on a held-out test set, and saves `cattle_breed_efficientnetv2s.pt` + `class_names.json`.

### 4. Run the API
```bash
python app.py
```
The API starts on `http://localhost:5000`, with interactive docs at `http://localhost:5000/docs`.

### 5. Try it out
Open `predict_test.html` in a browser and drop in a photo — or:
```bash
curl -X POST -F "file=@sample.jpg" http://localhost:5000/predict
```

##  Model

- **Architecture:** EfficientNetV2-S, pretrained on ImageNet, fine-tuned in two stages (frozen-backbone head training, then partial unfreezing at a low learning rate)
- **Evaluation:** accuracy, top-3 accuracy, per-class precision/recall, and a confusion matrix on a held-out test set never seen during training or tuning
- **Explainability:** Grad-CAM heatmaps overlaid on predictions to visually verify the model is using the animal's actual features rather than background cues

##  Dataset

Trained on breed images sourced from public datasets including [ICAR-NBAGR](https://www.nbagr.res.in/)-aligned collections and Kaggle/Roboflow cattle-breed datasets. Dataset not included in this repository due to size — see notebook comments for suggested sources.

# Cattle Breed Recognition — Backend

Node.js/Express + MongoDB backend for an image-based cattle breed recognition site.

## Architecture

```
Client (web/app)
      │  multipart/form-data (image)
      ▼
Express API  ──►  MongoDB (users, breeds catalogue, prediction history)
      │
      │  POST image
      ▼
ML model-serving endpoint (separate service, see below)
```

**Important:** this backend handles auth, image upload, storage, breed
metadata, and prediction history — but it does **not** train or run the
image-recognition model itself. Node isn't a natural fit for that; CNN
training/inference is normally done in Python (TensorFlow/Keras or PyTorch).

The recommended setup is:
1. Train an image classifier (e.g. fine-tune ResNet50/EfficientNet/MobileNet
   on labeled cattle breed photos).
2. Serve it behind a small HTTP endpoint (FastAPI or Flask) that accepts an
   image and returns JSON predictions.
3. Point this backend at that endpoint via `ML_SERVICE_URL` in `.env`.

`services/mlService.js` documents the exact request/response contract it
expects. Until you have that service running, in `NODE_ENV=development` it
automatically falls back to mock predictions so you can build and test the
rest of the app (routes, DB, frontend) independently.

## Setup

```bash
npm install
cp .env.example .env   # then edit values, especially MONGO_URI and JWT_SECRET
npm run dev             # nodemon, or `npm start` for plain node
```

Requires a running MongoDB instance (local or Atlas) at the URI you set.

## API Overview

| Method | Route                     | Auth        | Description                          |
|--------|---------------------------|-------------|---------------------------------------|
| POST   | /api/auth/register        | —           | Create account                        |
| POST   | /api/auth/login           | —           | Log in, get JWT                       |
| GET    | /api/auth/me              | required    | Current user profile                  |
| GET    | /api/breeds               | —           | List/search breed catalogue           |
| GET    | /api/breeds/:idOrLabel    | —           | Single breed by id or labelKey        |
| POST   | /api/breeds               | admin       | Add breed metadata                    |
| PUT    | /api/breeds/:id           | admin       | Update breed metadata                 |
| DELETE | /api/breeds/:id           | admin       | Remove breed                          |
| POST   | /api/predictions          | optional    | Upload image, get breed prediction    |
| GET    | /api/predictions/history  | required    | Logged-in user's past predictions     |
| GET    | /api/predictions/:id      | required    | Single prediction record              |

`POST /api/predictions` expects `multipart/form-data` with the file under
field name `image`. Example with curl:

```bash
curl -X POST http://localhost:5000/api/predictions \
  -F "image=@/path/to/cow.jpg"
```

## Notes / next steps

- Uploaded images are stored on local disk under `/uploads` and served
  statically. For production, swap this for S3/Cloud Storage and store the
  resulting URL instead (upload middleware and static serving would change
  accordingly).
- Add rate limiting (e.g. `express-rate-limit`) on `/api/predictions` before
  going public, since it triggers a call to your ML service on every request.
- Seed the `Breed` collection with your actual breed catalogue — `labelKey`
  must exactly match the class labels your trained model outputs so
  predictions can be enriched with metadata automatically.
